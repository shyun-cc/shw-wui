> **设计讨论稿 · 尚未实现。**

## 设计评审流程（拟议）

1. 提出使用场景：说明使用者、操作任务、输入、成功结果与失败情况。
2. 补充候选组件说明：描述职责、交互状态、键盘行为和边界，暂不承诺代码接口。
3. 对照验收标准评审，未确定内容进入问题清单。
4. 在决策记录中写明结论、理由、影响及状态。
5. 需求与验收获确认后，再另开业务实现变更；本稿本身不授权实现。

## 使用流程（待确认）

候选流程为“选组件 → 查看状态与约束 → 在应用中组合 → 验证交互与无障碍”。实际安装命令、导入方式、样式接入和升级路径均待技术栈决策后定义。

## 文档发布流程

修改 `docs/` → PR 构建检查 → 内容讨论 → 维护者审阅合并 → 默认分支工作流构建及 Pages 部署 → 检查实际公开页面。PR 只构建，不部署；草稿 PR 和本地构建不能作为上线证据。
